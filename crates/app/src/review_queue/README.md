# review_queue

The main window's view: the viewer's own pull requests, those that request their review, and others' open pull requests in the watched repositories (one tab each, grouped by repository, with a stack's layers grouped under its header), which one is selected, and when the lists refresh from GitHub. To review counts current direct review requests, including repeat requests. When a request belongs to a stack, every known layer appears in order. Layers outside the request list are dimmed and can be opened. The Others tab lists every watched repository, each with a filter that opens under its header; filtering happens here, on the fetched list, so changing a filter costs no request. The hidden branch rules (a preference) narrow all three tabs the same way: the queue keeps every fetched pull request for the refresh and shows them without the hidden ones. It hands the selected pull request to `pull_request_detail`, which shows it, and opens the stack layers the detail asks for, fetching one that is in no list; it does not load files or draw diffs. It also draws the bar across the window's top (panel toggles, tabs, refresh) and decides what stays selected across refreshes and relaunches. Which repositories are watched is a preference, changed in the settings window.

At launch, a saved selection gets priority, including a cached stack layer absent from the lists. Without a selection, Mine opens its first stack in sidebar order as a combined review, or its first standalone pull request when no stack exists. Folded repositories do not exclude candidates; the chosen repository is revealed. An empty cache waits for the first refreshed queue. Cached saved selections and automatic picks remain provisional until both own lists and Others finish refreshing, so either can fall back if its PR disappears. Locally re-filtering lists does not settle startup. When GitHub is unavailable or the initial refresh fails, a missing saved selection gives way to cached Mine instead of waiting indefinitely. A valid saved selection keeps its tab and scroll. Choosing a tab, PR or stack layer cancels the pending startup fallback, so a delayed refresh cannot replace the user's navigation. Later refreshes do not auto-select a different review.
