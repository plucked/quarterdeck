# pull_request_detail

The right pane for one pull request: a sticky header with the title and a collapsible description, a diff summary and every changed file laid out as a single virtualized list of small rows (a file header, a hunk header, one diff line), so only what is on screen is built, and a collapsible side panel with a file tree that filters what both show and marks files and folders viewed. A stacked pull request can be reviewed as its own layer or combined with the layers below it into one diff. It shows how far a load from GitHub has come. It loads the files (cache first, then GitHub), builds and colors their diffs off the main thread, fetches a file's text when the user reveals the unchanged lines around its hunks, and follows the diff settings and keeps each file's viewed and collapsed state. It does not choose which pull request to show or keep the queue; `review_queue` tells it, and it reports when it scrolls so the position can be saved. It also holds the review: GitHub's conversations and the user's comments under their lines, writing, editing and deleting them, and submitting a GitHub review or copying local notes for an agent.
