# pull_request_detail

The header's first row places status and repository on the left, Summary / Diff / Brief tabs in the center, and author, branches and update time on the right. The two-line title gets its own second row. Long metadata truncates with full text available on hover. Summary shows the PR's Markdown description in a scrollable reading column, with an empty state when none was provided; its scroll is kept across tab switches and reset for another PR. Selecting a file opens Diff. For stacked PRs, the tab bubble expands downward to reveal Layer / Combined only in Diff, then collapses in Summary or Brief while keeping the selected review mode. Its reveal reverses smoothly on quick tab changes and respects Reduce Motion. Stack positions and layer navigation live in the sidebar; range details, the range-start shortcut and stack errors remain available on hover over the selector.

The right pane for one pull request: a sticky header with the title and view tabs, a diff summary and every changed file laid out as a single virtualized list of small rows (a file header, a hunk header, one diff line), so only what is on screen is built, and a collapsible side panel with a file tree that filters what both show and marks files and folders viewed. Folder rows show recursive changed-file counts and line totals for files matching the active filters, including patchless moves or binaries. Optional theme-aware heat colors use those counts; Hide viewed excludes reviewed files, while collapsed folders still count matching descendants. A stacked pull request can be reviewed as its own layer or combined with the layers below it into one diff. It shows how far a load from GitHub has come. It loads the files (cache first, then GitHub), builds and colors their diffs off the main thread, fetches a file's text when the user reveals the unchanged lines around its hunks, and follows the diff settings and keeps each file's viewed and collapsed state. It does not choose which pull request to show or keep the queue; `review_queue` tells it, and it reports when it scrolls so the position can be saved. It also holds the review: GitHub's conversations and the user's comments under their lines, writing, editing and deleting them, and submitting a GitHub review or copying local notes for an agent. The side panel has four tabs: the file tree, the review, the actions (merging, also as admin, or closing the pull request on GitHub and deleting its branch) and the checks of its head commit (drawn by `checks_panel`, which this pane only points at the shown pull request and tells when it is on screen). It can also show, in place of the diff, a brief that Claude Code writes about the change: it starts the run, follows its progress, and draws the brief's widgets, quoting code from the loaded diff and jumping from any quoted lines to the diff.

The top file's header stays pinned over the diff once it scrolls out of view, with the same collapse, tree and viewed controls. The next file's header pushes it away. This overlay uses the list's current layout without changing row heights or scroll anchors.

The Files tab's Smart row generates an ordered review plan with local Claude Code (Opus at high effort), using the shared confined runner and the loaded PR or combined-range diff. A scope keeps its saved plan while a replacement runs, survives navigation, and restores from SQLite after relaunch. The head and base SHA flag stale plans; their exact saved file membership never expands to new files. Smart chip choices intersect Kind, Type and Hide viewed in both the tree and diff, including facet counts and folder summaries. Suggested mechanical buckets have an explicit bulk-viewed checkbox, disabled for stale plans. Cancelling stops the run; missing CLI, failed output validation and persistence errors remain visible in the row.
