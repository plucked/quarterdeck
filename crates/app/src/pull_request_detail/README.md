# pull_request_detail

The header's first row places status and repository on the left, Summary / Diff / Guided review / Brief tabs in the center, and author, branches and update time on the right. The two-line title gets its own second row. Long metadata truncates with full text available on hover. Summary shows the PR's Markdown description in a scrollable reading column, with an empty state when none was provided; its scroll is kept across tab switches and reset for another PR. Selecting a tree file opens Diff; selecting a guided step or one of its members stays in Guided review. For stacked PRs, the tab bubble expands downward to reveal Layer / Combined in Diff and Guided review, then collapses in Summary or Brief while keeping the selected review mode. Its reveal reverses smoothly on quick tab changes and respects Reduce Motion. Stack positions and layer navigation live in the sidebar; range details, the range-start shortcut and stack errors remain available on hover over the selector.

The right pane for one pull request: a sticky header with the title and view tabs, a diff summary and every changed file laid out as a single virtualized list of small rows (a file header, a hunk header, one diff line), so only what is on screen is built, and a collapsible side panel with a file tree that filters what both show and marks files and folders viewed. Folder rows show recursive changed-file counts and line totals for files matching the active filters, including patchless moves or binaries. Optional theme-aware heat colors use those counts; Hide viewed excludes reviewed files, while collapsed folders still count matching descendants. A stacked pull request can be reviewed as its own layer or combined with the layers below it into one diff. It shows how far a load from GitHub has come. It loads the files (cache first, then GitHub), builds and colors their diffs off the main thread, fetches a file's text when the user reveals the unchanged lines around its hunks, and follows the diff settings and keeps each file's viewed and collapsed state. It does not choose which pull request to show or keep the queue; `review_queue` tells it, and it reports when it scrolls so the position can be saved. It also holds the review: GitHub's conversations and the user's comments under their lines, writing, editing and deleting them, and submitting a GitHub review or copying local notes for an agent or sending them to an active Claude Code session. While the Claude picker is open, the note count and actions remain visible, the full note preview is hidden until it closes, and the picker fills the remaining side-panel height. The inline Claude picker receives the same Markdown export, refreshes on open and before submission, and is closed when notes or scope change. Sent notes remain saved; receipt and replies are checked in Claude. The side panel has four tabs: the file tree, the review, the actions (merging, also as admin, or closing the pull request on GitHub and deleting its branch) and the checks of its head commit (drawn by `checks_panel`, which this pane only points at the shown pull request and tells when it is on screen). It can also show, in place of the diff, a brief that Claude Code writes about the change: it starts the run, follows its progress, and draws the brief's widgets, quoting code from the loaded diff and jumping from any quoted lines to the diff.

The top file's header stays pinned over the diff once it scrolls out of view, with the same collapse, tree and viewed controls. The next file's header pushes it away. This overlay uses the list's current layout without changing row heights or scroll anchors.

The side panel shares the middle pane's rounded tab treatment. Its bubble expands to reveal GitHub / Local for a single PR's Review tab, or Merge / Close for Actions when GitHub is connected. The last options stay mounted while the bubble closes, with hidden handlers guarded and Reduce Motion respected. Combined reviews keep their local-only explanation in the body. Selecting an action prepares it; existing confirmations still govern execution, and switching or cancelling cannot replace a running operation. Narrow panels use smaller tab spacing and omit the review count from the tab (the body retains it).

The native Focus Drawer follows the main review surface: Files shows the tree in Diff; Guide shows the walkthrough in Guided review. Their navigator choice is restored at launch; Summary and Brief retain the last navigator. Two header rows contain scoped search and the filter drawer toggle, then a horizontal viewed count/bar, Hide viewed and Reset. Kind and Type filters live in the optional drawer. Guide buckets belong only to Guided review; they do not filter the ordinary file tree. Folder checkboxes reflect and toggle the viewed marks of descendants matching the current filters, including matches under folded folders. Folder, group, bucket and reset actions remember the original marks and folds for one Undo, bound to each file's patch fingerprint.

Path search ranks case-insensitive fuzzy tokens. Content search loads full text at the shown head (or base for deleted files), first from the content-addressed cache, then GitHub, on the background executor. Query work is debounced and cancellable. The virtualized result list shows up to three matching source lines per file; a click opens a bounded source excerpt, including lines outside the diff. Coverage reports checked files, unavailable binaries or texts over 8 MB, and failures. Partial results remain usable, and Retry respects GitHub's throttling deadline. Changing the review target cancels indexing and discards old text.

Guided review uses local Claude Code (Opus at high effort) with the confined runner and the loaded PR or combined-range diff. It preserves the saved plan during generation, cancellation or failure. Typed SQLite tables store ordered buckets, ordered reading items, guidance and exact member paths in the model's chosen sequence. One item can group related binary or mechanical files; expanding it reveals its real members, and its checkbox covers the whole group. The group overview’s Next in order and Mark group viewed actions continue across buckets, skipping completed or filtered-out items and treating a group as one stop. They wrap to unfinished earlier items after reaching the end; if none remain, the completed group stays open. Unmarking and sidebar checkboxes leave the reader in place. The V shortcut follows the same order. Bucket Next stays within its bucket. Bucket marking covers all members. New files outside an outdated plan appear explicitly ungrouped; saved membership never expands silently. Old plans migrate to individual items until refreshed. The navigation is a virtualized list of small copyable row descriptors. Shaded bucket headers, file-type icons and explicitly labeled file groups separate the hierarchy. Item and bucket guidance wrap at the drawer width; the item and its guidance share one measured row. Every step, including a single-file step, opens one guided diff workspace with its note and ordered members. All members start expanded on entering a new step. Clicking a file header toggles its diff in place; marking a file viewed collapses it, and unview or Undo restores its prior disclosure. Manual disclosures survive refreshes. Guided review keeps its selected step, disclosures and scroll separate from the full diff across main-tab switches; selecting another step initializes that step. Keyboard file navigation follows member order. Sidebar members carry their owning step so repeated files in different buckets retain the correct guidance. Inline diffs reuse syntax coloring, context expansion, selection, comments and viewed controls, with file and line rows virtualized. The main Diff tab returns to ordinary browsing at its retained scroll position; the Guided review tab resumes the selected step, or the first visible unfinished step after loading a new guide.

Guided generation uses a per-run authenticated MCP endpoint. Claude authors complete bucket replacements, receives overlap and coverage diagnostics, repairs the draft, and seals a receipt. The app publishes only after matching that receipt to a successful CLI result and exit. `ReviewPublicationGate` arbitrates cancellation versus publication without blocking the UI; a captured scope/revision and SQLite run reservation prevent older generations from overwriting newer ones. Refreshing that scope to a different revision cancels an active draft. The previous saved guide remains usable throughout generation and survives errors. A completed draft that fails to save retains its exact artifact, receipt, cost and audit for this session. Retry save only retries local publication under the original reservation; Discard, a new generation or a changed head/base removes the pending draft. Each save attempt has a fresh cancellation gate; transaction failure releases its claim, and revision changes observed during a save prevent stale retries. Progress distinguishes reading, building coverage and repairing validation issues.

Brief generation uses the same MCP process lifecycle and publication gate, with strict page/widget/anchor repair. `BriefPane` keeps a saved brief and its page visible while a rewrite runs, overlays compact progress or retry status, disables duplicate writes, and rejects stale progress/completions. Successful replacement resets list measurements even when page and widget counts match. Refresh cancels active drafts whose captured head or base differs. Reports keep the full accepted artifact separately from the publication receipt and repair audit. Brief save failures use the same retained-draft Retry save/Discard lifecycle, keeping the prior page readable until a successful replacement.

Individual PR file loads reuse the cache while the commits match. A changed revision with more than 500 files tries the compare diff download first, then paginated files if the download fails or is incomplete. GitHub throttling stops the attempt. Only a complete file set is cached; the API's 3,000-file cap must not silently omit the rest.
