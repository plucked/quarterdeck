# Quarterdeck (app)

| Module | Holds |
|---|---|
| `launch_app` | gpui start-up; opens the main window at its saved placement or centered, hidden behind the startup splash when the movie is there (`StartupMode`) |
| `main_window` | `MainWindow` root view: owns `ReviewQueue`, records window placement, writes UI state on focus loss; `MainWindowReveal` (hidden behind the splash, fading in, shown) |
| `startup_splash` | `StartupSplash`: borderless see-through `PopUp` window (1000×300 pt, centered on the main window's display) playing the startup movie from `decode_splash_frames` (the version in its bottom right corner, `theme::on_splash`, once a frame shows) (its own thread: `qd_video::VideoReader` is not `Send`; bounded `futures` channel, 20 frames ahead; each frame a `RenderImage`, the previous one freed with `drop_image`), paced by the screen: `on_screen_refresh` runs before every frame gpui draws (`cx.on_next_frame`, re-registered each time) and `SplashPlayback` picks the newest frame due (half a frame early counts, so refresh jitter never decides; timer-driven frames stuttered against the display), starting once 10 frames are decoded and holding the clock when the decoder falls behind; at the end or on a click it calls `MainWindow::reveal`, waits for the main window's first frame (its second refresh; 500 ms at most: ~100 ms in a debug build) and only then fades out (`STARTUP_FADE`, 1 s) and closes, so the fade does not start with a jump; `startup_video_path` (bundle `Resources`, else the source tree) |
| `app_commands` | actions (`Quit`, `OpenSettings`, `CloseWindow`, `Refresh`, `Copy`, `NextFile`, `PreviousFile`, `MarkViewedAndNext`, `ToggleFileTree`, `ToggleSidebar`, `NextLayer`, `PreviousLayer`, `ToggleStackReview`, `ShowAuthored`, `ShowReviewRequested`, `ShowOthers`, `CheckForUpdates`), key bindings, menu bar, `REVIEW_QUEUE_CONTEXT` |
| `app_settings` | `AppSettings` global: the preferences (color theme, diff view settings, cache TTL, watched repositories of the Others tab), loaded at launch, saved on change, observed by views |
| `settings_window` | settings window (cmd-,, single instance, 860×680, pages scroll): category list + page per `SettingsCategory` (Appearance: theme cards in a Light and a Dark row (strip in the theme's own colors, name, purpose; click applies at once) and `render_theme_preview` below, a PR header + hunk drawn in the hovered theme's colors, else the active one's; File Diff; GitHub: account (where the token comes from, sign out of a saved one, a `TextArea` to paste a token: `GitHubClient::viewer` checks it, `store_token` saves it, then `relaunch_after_exit` + quit), cache TTL, cache size on disk with a breakdown per kind (read in the background on open and after clearing), clear cache, API usage; Repositories: add a watched repository (one-line `TextArea`, return adds; parsed by `RepoRef::parse_input`, checked with `GitHubClient::repository`, saved as GitHub spells it), quick picks from the queue's cached lists (read in the background on open), the list with Remove; Updates: version, `UpdateStatus`, Check now, Restart to update and the release notes in a `MarkdownView` when ready), `SettingRow` component; `open_settings_window_at(category)` |
| `app_services` | `AppServices`: GitHub client (or reason it is missing), its `TokenSource`, cache; also a gpui global for other windows |
| `app_update` | `AppUpdater` (gpui global entity, observed by the top bar and the settings window): `RunningBundle::locate` in the background at launch (removes leftovers), first check after 15 s, then every 4 h (timer re-armed per check); `decide_update` (download only a release newer than the running and staged versions); download + stage in the background → `UpdateStatus::Ready` (notes parsed); `restart_to_update` installs in the background, then `relaunch_after_exit` + quit; `on_app_quit` installs a ready update synchronously (two renames; gpui waits only 100 ms for quit futures). Menu: Quarterdeck → Check for Updates… (checks, opens Settings → Updates) |
| `scrollbar` | `VerticalScrollbar`: reusable draggable scrollbar for a `ScrollbarTarget` (`ScrollHandle`, `ListState`, or `ListState` + `ListRowTops` estimates; gpui draws none) |
| `shared_cache` | `SharedCache`: `Arc<Mutex<GitHubCache>>` with poison-tolerant `lock` |
| `fetch_stack` | `cached_stack` / `refresh_stack`: a stack's layers from the cache, and checked with GitHub (conditional), used by the queue and the detail |
| `ui_state` | `UiStateRecorder` global (reads saved UI state, batches writes) and window placement conversion |
| `diff_view` | per-row diff rendering (file header, hunk header, gap bar, unified line, split row, note, card framing) and `DiffSummaryBar`; `GapPart`, `FileTextLoad` |
| `segmented_control` | `SegmentedControl`: reusable row of exclusive options; `fill_width` spans its container |
| `text_area` | `TextArea`: multiline text editor entity (gpui has none): typing through the system input handler (IME), selection, word/line moves, copy/cut/paste, cmd-enter → `TextAreaEvent::Submit`, escape → `Cancel`; key context `TextArea` |
| `panel_toggle` | `PanelToggle` + `PanelEdge`: icon button drawn as a window outline with the panel's strip (filled while shown), for the top bar |
| `button` | `Button`: small text button (plain, ghost, primary, danger; selected, disabled) |
| `facet_chips` | filter chips shared by the file tree's filter and the Others filters: `render_chip` (picked / hidden / open, dimmed at 0), `render_chip_row` (small uppercase label column), `render_more_chip`, `most_common_values` (`COLLAPSED_CHIPS` = 8), `ChipClick::of` (⌥-click hides) |
| `repo_monogram` | `RepoMonogram`: a repository's first letter on a color picked from its name (`theme::label_colors`), in the sidebar and the Repositories settings |
| `fold_chevron` | `FoldChevron` + `FoldState`: the 24 px fold button (▶ / ▼, tints on hover; its own click or the row's), used for every fold: sidebar repositories and stacks, tree folders, diff file headers, the description; rows without one leave `FOLD_CHEVRON_SIZE` of room |
| `checkbox` | `Checkbox` + `CheckState` (unchecked, checked, mixed): a drawn checkbox, used for viewed marks and options |
| `display_date` | `short_date`: a GitHub timestamp as `21 Oct 2026`; `relative_age`; `unix_seconds` (the Others filter's Updated within) |
| `display_size` | `byte_size`: a byte count as `151.7 MB` |
| `resize_handle` | `ResizeHandle`: reusable divider strip between two panels in a flex row; dragging it reports a clamped width (`ResizeEdge` says which side the panel is on) |
| `markdown_view` | `MarkdownView`: reusable component rendering a `qd_markdown::MarkdownDocument`, with mouse text selection and copy |
| `theme` | colors and fonts: eight color themes (`qd_cache::ColorTheme`; the Proofreader Palettes: Ledger, Vellum, Overcast, Signal light; Graphite (default), Tide, Lantern, Beacon dark), each a `Palette` of ~20 designed colors from which `ThemeColors` works out the rest (surfaces step from the background toward the text; `muted`/`subtle` text faded only as far as 6:1 / 4.5:1 allow; `success`/`danger` from the palette's string/error colors; diffs blue/orange); the active theme is a process-wide atomic set by `AppSettings` (views call plain functions like `theme::text()`, `theme::syntax(kind)`; colors are read while drawing, so `cx.refresh_windows()` applies a switch); `colors_of(theme)` for previews; `on_label` white on `label_colors`; Schibsted Grotesk for the interface, JetBrains Mono for code |
| `bundled_fonts` | `load_bundled_fonts`: registers the static TTFs in `assets/fonts` (OFL; Schibsted Grotesk 400/500/600/700/italic, JetBrains Mono 400/700 + italics) at launch; static cuts because gpui would show only a variable font's default weight |
| `review_queue` | main view: the top bar (sidebar toggle, refresh, title, Restart to update when an update is ready, side panel toggle), the sidebar with Mine / Review / Others tabs atop its lists (`QueueLists`; Others: `OthersTab` keeps the watched repositories, each one's `OthersFilter`, the passing PRs the rows index into (`shown_list`), the open filter and expanded chip rows; `others_filtering` decides what passes and the chip counts, labels match any picked one; `QueueRow::build_others` lists every watched repository, then `OthersFilter` / `NothingShown` rows), pull requests grouped by repository and stack in the sidebar (`QueueRow`, `CollapsedGroups`), selection by id (`SelectionOrigin`), opening stack layers in no list, refresh schedule, restore; owns the detail view |
| `pull_request_detail` | `PullRequestDetail` view: sticky header (title, meta, stack bar, collapsible description, activity pill + progress line), files as one virtualized `list` of `DetailRow`s, side panel (Files / Review tabs); `ReviewTarget` (layer / combined range), loads files with `LoadProgress`, builds/colors diffs, settings, viewed/collapsed, filters |

- Key bindings: `cmd-,` settings, `cmd-w` close window (settings window handles it), `cmd-r` refresh, `cmd-c` copy (handled by the focused view, e.g. a `MarkdownView` with a selection), `cmd-q` quit, `cmd-b` side panel, `ctrl-cmd-s` sidebar. `cmd-1`/`cmd-2`/`cmd-3` Mine / Review / Others tab. Single keys only in `ReviewQueue && !TextArea` (the queue's context, not while a text area has focus): `]`/`[` next/previous shown file, `v` mark the top file viewed and jump to the next unviewed one, `}`/`{` next/previous stack layer, `c` layer ↔ combined review. The queue handles them and delegates to the detail.
- Settings: a new preference goes in `AppSettings` (field + setter that saves), gets a `SettingRow` on its category's page (new categories: a `SettingsCategory` variant + page), and views read it with `AppSettings::…(cx)` and `observe_global::<AppSettings>`. The main view shows no option controls.
- Markdown: parse once when the source changes (`ReviewQueue::set_selected_index` parses the description), keep `Arc<MarkdownDocument>`, render with `MarkdownView::new(id, document.clone())`. Links open only if `http(s)://`; the text comes from other people.
- Markdown selection: state via `window.use_keyed_state` keyed by (view id, `Arc` pointer of the document), so a new document starts unselected; keep the `Arc` stable while the source is unchanged (`ParsedDescription`). Each frame records every text's `TextLayout` for hit testing; drags are tracked by window-wide mouse listeners registered in a `canvas` paint. Copy joins texts with `\n`. A press released without a drag is a link click.
- Review pane layout: the sticky header and the diff form one column; the side panel (Files / Review) sits beside that column at full height, from the top bar down.
- Review pane: the sticky header shows title + meta; viewed progress shows only in the side panel (the tree header's `x of y viewed` and progress bar), not in the header or the summary bar; the description is collapsed by default and again for each new PR, scrolling inside the header past 320 px. Files are ordered by `FileTree::file_order()` (folders first) once at load, so the tree and the diff share one order and file indexes. The tree (`uniform_list`, 24 px rows) has a progress bar, the filter (`filter_rendering.rs`): a Hide viewed switch, a Kind row (Code/Tests/Generated/Moved, one kind per file) and a Type row (extension, or the name of a file without one; alphabetical by name without the dot, ignoring case; collapsed it shows the 8 with the most files + more), where a click picks a chip (show only the picked ones of that row; rows narrow together), ⌥-click hides it (struck through), counts say what a chip would show given the other row (0 is dimmed), and a summary line `Showing x of y · … · Reset` (or the chip hint) right above the tree, with a ghost `Collapse all` / `Expand all` button at its right (one button that turns into the other, so it fits the narrowest panel; `Collapse all` while any folder is expanded, nested folders included; hidden for a flat list); right-aligned columns on every row: added / removed lines (monospace, sized for the largest top-level folder's sums so they line up; a folder sums the files under it; zero is blank), the file's status badge (`render_file_status_badge`, shared with the file header; none for a plain modification), and the viewed box: tri-state for folders (mark all / unmark all); it highlights the file at the top of the diff; clicking a file scrolls to it. A file the filter hides keeps an empty row range (`DetailRowList::file_start` is `None`), so it vanishes from the diff too; `AllFilesHidden` says why the diff is empty. Tree visibility, Hide viewed and hidden kinds persist (`ReviewLayoutState`); picked chips, file types and collapsed folders reset per PR. The empty diff names what narrows it.
- Sidebar look: repository headers carry a `RepoMonogram` (first letter on a color picked from the name via `theme::label_colors`), the name, owner, a count pill and a `FoldChevron`; groups after the first start below a divider. A pull request row has an open (green) / draft (grey) ring, its title on up to two lines, `#n · author · age` (`relative_age`) and a Draft pill; stack headers a drawn stack glyph.
- Sidebar grouping: each tab's list is grouped by repository (`QueueRow::RepoHeader`: name, owner, count; repositories in the order of their most recently updated pull request); clicking a header folds the group (`CollapsedGroups`, with folded stacks), saved as UI state (`FoldedGroups`, restored at launch). Rows under it leave the repository out of their metadata.
- Stacks: the queue's refresh fills `PullRequest::stack` (GraphQL; on failure the last known memberships stay). The sidebar groups a stack under a header at the place of its most recently updated listed layer, with every layer bottom first once its layers are known, one line each (position, title, `#number`) so long stacks stay compact (the sidebar is a variable-height `list`; `rebuild_rows` resets it and puts the scroll position back) (`QueueRow::OtherLayer` for layers the tab's list lacks: muted, clicking opens them; ⇧-click on a layer of the shown stack starts the combined range there, `PullRequestDetail::start_combined_at`); layers asking for the viewer's review carry a Review badge, and the header says how many are yours / to review. The queue keeps the listed stacks' layers (`stacks`): read from the cache at launch, checked with GitHub after each refresh (`fetch_stack.rs`, shared with the detail; free on 304); clicking the header opens the combined review (highest listed layer, from the lowest unmerged one) and highlights it while shown (`DetailEvent::TargetChanged` redraws the sidebar); its chevron collapses the group. The detail reads the stack from the cache, then checks it with GitHub on every shown version (free on 304), and shows the stack bar (layer N of M, ‹ › neighbours, Layer/Combined, the combined range); the sidebar is the stack's map. Opening a layer emits `DetailEvent::OpenLayer`; the queue selects it from a list or fetches it (`pull_request_by_number`, cached, `SelectionOrigin::StackLayer`, survives refreshes). `ReviewTarget::decide`: combined = base of the first layer (the chosen start, else the lowest unmerged) to the head of the shown layer; it waits (`AwaitingStack`) for the layers. Combined viewed marks are their own `ReviewScope`. The review mode persists in the review layout.
- Review comments: a `+` left of each diff line (on hover), or a double click on the line (the side clicked, in a split row; it replaces double-click word selection there), opens the composer under it (shift-click another line's `+` to span lines); the lines of the comment being written or edited are tinted (`comment_range`); cards (`DetailRow::CommentCard`, built by `ReviewComments::cards` and placed by `CommentPlacement`) show GitHub conversations (comments with edit/delete when permitted, draft replies, reply, resolve/reopen) and the user's notes (edit/delete), under their line or, outdated, under the file header. GitHub and local cards show together on a single pull request. New comments go to the destination picked in the composer (or the Review tab), remembered in the review layout (`comment_destination`): GitHub (drafts in `review_notes`, submitted with a verdict and summary as one review; drafts are dropped as GitHub takes them) or Local (notes to copy as Markdown for an agent: file, lines, a diff excerpt with 2 lines of context, the note). Combined reviews are local only. GitHub's conversations are read once per shown PR (one GraphQL request, not cached); edits, deletions and resolving go to GitHub at once and re-read the conversations. Only one editor is open at a time (`CommentEditor`); its row is re-measured as it grows (searched in its file's rows only). Opening, saving, cancelling and deleting a comment rebuild only the affected file's rows (`refresh_comment_files`), never the whole list: a full rebuild re-measures every row and is slow on big PRs.
- Pull request actions: `Merge…` / `Close…` in the header open a panel under it (`ActionPanel`) that reads GitHub's options when it opens (one GraphQL request): readiness, the repository's allowed methods, merge queue, permissions. Merge offers the allowed methods, `Merge as admin` (bypass rules) when the viewer may and requirements are unmet, and a stacked PR's note that the unmerged layers below merge too; every action is confirmed in a second step. The merge is followed (poll every 1.5 s, up to 3 min); the head branch is deleted afterwards when ticked (ticked by default for a close; for a merge only when the repository does not delete merged branches itself; never for forks or when an open layer above is based on it). A PR already merged or closed offers `Delete branch` while its branch exists. A PR merged or closed here stays selected (`SelectionOrigin::Finished`) so the outcome stays in view. Success emits `DetailEvent::PullRequestChanged` and the queue refreshes.
- Loading indicator: the background load reports `LoadProgress` through a `futures` mpsc channel (checking commits, files n of total from `RevisionCheck`, MB of a combined diff in 256 KB steps, building diffs); the header pill (pulsing dot), a progress line under the header (determinate when the share is known, else sweeping) and a loading card in place of the files show it; stack checks and syntax batches show in the pill too. The sidebar pulses while refreshing or opening a layer.
- Diffs: built on the background executor when files load and when whitespace/highlight settings change (layout/wrapping only redraw); `LoadedFile` holds `Arc`s of file + diff. `FileReviewState` owns viewed/collapsed per file; viewed marks persist with a `PatchFingerprint` and reset when the patch changes. Files over 400 changed lines and viewed files start collapsed.
- Context lines: a hunk header with hidden lines above it is a gap bar (`render_gap_bar`: `↓ 20 lines` below the hunk above, `↑ 20 lines` above the hunk below, `Show all N`; a gap of ≤ 20 shows whole in one click; the top of the file only grows up, the end only down), and `DetailRow::EndGap` is the bar below the last hunk (length unknown until the text is fetched). Added, deleted and binary files have no gaps. The first click fetches the file's text (`fetch_file_text`: cache by blob SHA, else GitHub; head commit from `file_set_commits` or the combined range); `ContextLoads` holds the load state, the lines clicked open while loading (all revealed when the text arrives) and the tasks per file index (reset per load); a cached text found by an abbreviated SHA is used only when the patch matches it (`FileDiff::is_patch_of`), else fetched; a failed cache write is reported on stderr, not fatal. `LoadedFile` keeps the patch's diff, the `FileContext` (text + `RevealedLines`) and its gaps; `diff` is the patch's with the revealed lines (`FileDiff::with_context`), kept across settings rebuilds (`keeping_context_of` carries lines revealed while a rebuild ran). A reveal rebuilds that file's rows only and colors its grown diff in the background. Revealed lines (`LineOrigin::FileText`) get no `+` comment button: GitHub takes comments only on patch lines.
- Syntax colors: after load and after a rebuild, `highlight_syntax` runs one background batch per core and applies each batch as it finishes (matched by the diff's `Arc`, so a rebuilt diff ignores stale colors). Files draw plain until then. A real 99-file / 4.5k-line PR takes ~0.7 s single-threaded; `code_highlights` merges syntax colors with changed-range backgrounds into non-overlapping runs.
- GitHub usage (`fetch_changed_files`, `fetch_combined_files`, `fetch_stack`): files cached for the PR's `updated_at` → no request; otherwise one commit check (`pull_request_revision`, conditional on the stored ETag, free when unchanged) → same commits: confirm the cached files; new commits or nothing cached: fetch all pages and cache. Past `MAX_LISTED_FILES` (3000, GitHub's list limit) the files come from one compare `.diff` download of the PR's base and head commits instead (the PR's own `.diff` stops at 300 files): seed#23891, 17,485 files, 156 MB in ~10 s. Large file counts stay quick: each `LoadedFile` keeps its `FileFacets` (kind, type), viewed marks match through a map, the file at a row is a binary search, and viewed counts read `FileReviewState::viewed_count`. Measured on a real 130-file PR: relaunch 0 core requests, after a comment 1, cold 3. A combined range is read from the cache by its two commits, else one `.diff` download. The queue refresh is 2 search requests (+1 per 10 watched repositories and page) + 1 GraphQL request; after it, `delete_expired(AppSettings::cache_ttl)` runs.
- Flow: show cached queue at launch → refresh from GitHub in background → cache → clean up expired data.
- Panel widths: the sidebar (240–720 px, default 380) and the side panel (220–640 px, default 300) resize by dragging the `ResizeHandle` between panels (the handle is the divider line, not a border, so it overlaps no scrollbar); each owner keeps its width and records it (`record_sidebar_width` / `record_side_panel_width`, batched writes).
- Restore: window placement, panel widths, sidebar visibility, folded repositories and stacks, queue tab, selected PR by id (matched against the cached lists, else a cached PR in no list (a stack layer), then the first refreshed lists, else dropped), detail scroll as `DetailScrollPosition` (row + offset; applied when the files load, so no heights are needed).
- Performance: the detail pane lays out only the rows on screen (`list`, overdraw 600 px, no `measure_all`: measuring every row of seed#16354, 1453 files, blocked the window ~10 s and took 5 GB). The scrollbar uses `ListRowTops` from `estimate_row_tops` (exact for fixed-height rows, wrapped lines by character count at the pane width, typical heights for comment cards), re-estimated when the rows or the width change (62k rows: 9 ms in a debug build). The file tree's folder rows read `FolderSummary`s (lines, viewed state) worked out once per `refresh_rows`, never per frame. Layout and text shaping need the `Window`, so they stay on the main thread; diff building and syntax colors run on the background executor. Collapse/viewed toggles and comment changes rebuild one file's rows and `splice` only the part that changed (`ChangedRows`; comment rows always count as changed), then put the top row back: gpui's `splice` moves the scroll to the start of any spliced range holding the top row; settings/load `reset` and re-anchor on the file at the top. Benchmark (100-file PR, split + wrap, 45 px/frame): 273 ms → 8.3 ms per frame. Scroll mode scrolls each file sideways via a per-file offset on horizontal gestures (rows are separate, so no per-file scroll container).
- Scrollbars: wrap the scroll container in a `relative()` div with the container `size_full()` and a `VerticalScrollbar` beside it: `ScrollbarTarget::Handle` for a div or `uniform_list` (`handle.0.borrow().base_handle.clone()`), `ScrollbarTarget::List` for a `list`. The thumb is painted at paint time.
- Diff selection: `DiffSelection` (side + anchor/head as row + byte) lives in `PullRequestDetail`, so it survives scrolling; cleared on any row rebuild/splice. Each painted code cell registers its `TextLayout` in `CodeSegments` from a paint-time `canvas` (only painted texts, so bounds exist; measured-only rows never register); the registry is cleared in `render`. Drag past the pane edge autoscrolls; split selections stay in one column; copy (`selected_diff_text`) is code only. A press outside code clears the diff selection without taking focus, so the description keeps its own selection.
- Wrapping text in a flex row needs `min_w_0()` on its flex item (see the skill's gpui rules); the detail pane and Markdown list items have it.
- Window display: gpui reports and takes window bounds relative to the window's display, so the placement saves the display's UUID (`display.uuid()`, stable across reconnects) and `launch_app` reopens with `display_id`; a missing display falls back to the main one, and placements that do not fit their display open centered.
- gpui on macOS opens windows by content size but reports `window_bounds` as the frame: save `viewport_size` for windowed mode. With the transparent title bar the content fills the frame, so both match (measured: a 1200×800 window reopens at 1200×800).
- Title bar: the main window's is transparent (`appears_transparent`, traffic lights at 14,13); the queue's 40 px top bar takes its place, leaving 84 px for the traffic lights. macOS keeps dragging the window by the bar's empty parts; a double click calls `titlebar_double_click`. The settings window keeps the system title bar.
- Look: the active theme (see `theme`): green and red never mean added/removed, only success/danger; the diff's `+`/`-` marks take the added/removed colors and line numbers the palette's line-number color; one accent (light blue) for selection and primary actions; secondary actions are ghost buttons; pills (`rounded_full`) for badges, chips and status; cards are `surface` with a strong border; small uppercase `subtle` labels head panel sections; checkboxes are drawn (`Checkbox`), never glyphs.
- UI changes are verified by running the app; view logic that can be tested without a window lives in plain types (`SelectionAfterRefresh`, `SelectionRestore`, `RefreshSchedule`).
