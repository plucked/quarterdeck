# quick-check (app)

| Module | Holds |
|---|---|
| `launch_app` | gpui start-up; opens the main window at its saved placement or centered |
| `main_window` | `MainWindow` root view: owns `ReviewQueue`, records window placement, writes UI state on focus loss |
| `app_commands` | actions (`Quit`, `OpenSettings`, `CloseWindow`, `Refresh`, `Copy`, `NextFile`, `PreviousFile`, `MarkViewedAndNext`, `ToggleFileTree`, `NextLayer`, `PreviousLayer`, `ToggleStackReview`, `ShowAuthored`, `ShowReviewRequested`), key bindings, menu bar, `REVIEW_QUEUE_CONTEXT` |
| `app_settings` | `AppSettings` global: the preferences (diff view settings, cache TTL), loaded at launch, saved on change, observed by views |
| `settings_window` | settings window (cmd-,, single instance): category list + page per `SettingsCategory` (File Diff; GitHub: cache TTL, clear cache, API usage), `SettingRow` component |
| `app_services` | `AppServices`: GitHub client (or reason it is missing) + cache; also a gpui global for other windows |
| `scrollbar` | `VerticalScrollbar`: reusable draggable scrollbar for a `ScrollbarTarget` (`ScrollHandle` or `ListState`; gpui draws none) |
| `shared_cache` | `SharedCache`: `Arc<Mutex<GitHubCache>>` with poison-tolerant `lock` |
| `fetch_stack` | `cached_stack` / `refresh_stack`: a stack's layers from the cache, and checked with GitHub (conditional), used by the queue and the detail |
| `ui_state` | `UiStateRecorder` global (reads saved UI state, batches writes) and window placement conversion |
| `diff_view` | per-row diff rendering (file header, hunk header, unified line, split row, note, card framing) and `DiffSummaryBar` |
| `segmented_control` | `SegmentedControl`: reusable row of exclusive options |
| `resize_handle` | `ResizeHandle`: reusable divider strip between two panels in a flex row; dragging it reports a clamped width (`ResizeEdge` says which side the panel is on) |
| `markdown_view` | `MarkdownView`: reusable component rendering a `qc_markdown::MarkdownDocument`, with mouse text selection and copy |
| `theme` | colors and fonts |
| `review_queue` | main view: Mine / Review tabs (`QueueLists`), stacks grouped in the sidebar (`QueueRow`), selection by id (`SelectionOrigin`), opening stack layers in no list, refresh schedule, restore; owns the detail view |
| `pull_request_detail` | `PullRequestDetail` view: sticky header (title, meta, stack bar, collapsible description, activity pill + progress line), files as one virtualized `list` of `DetailRow`s, side panel (stack map + file tree); `ReviewTarget` (layer / combined range), loads files with `LoadProgress`, builds/colors diffs, settings, viewed/collapsed, filters |

- Key bindings: `cmd-,` settings, `cmd-w` close window (settings window handles it), `cmd-r` refresh, `cmd-c` copy (handled by the focused view, e.g. a `MarkdownView` with a selection), `cmd-q` quit, `cmd-b` file tree. `cmd-1`/`cmd-2` Mine / Review tab. Single keys only in `REVIEW_QUEUE_CONTEXT` (the queue root's key context): `]`/`[` next/previous shown file, `v` mark the top file viewed and jump to the next unviewed one, `}`/`{` next/previous stack layer, `c` layer ↔ combined review. The queue handles them and delegates to the detail.
- Settings: a new preference goes in `AppSettings` (field + setter that saves), gets a `SettingRow` on its category's page (new categories: a `SettingsCategory` variant + page), and views read it with `AppSettings::…(cx)` and `observe_global::<AppSettings>`. The main view shows no option controls.
- Markdown: parse once when the source changes (`ReviewQueue::set_selected_index` parses the description), keep `Arc<MarkdownDocument>`, render with `MarkdownView::new(id, document.clone())`. Links open only if `http(s)://`; the text comes from other people.
- Markdown selection: state via `window.use_keyed_state` keyed by (view id, `Arc` pointer of the document), so a new document starts unselected; keep the `Arc` stable while the source is unchanged (`ParsedDescription`). Each frame records every text's `TextLayout` for hit testing; drags are tracked by window-wide mouse listeners registered in a `canvas` paint. Copy joins texts with `\n`. A press released without a drag is a link click.
- Review pane: the sticky header shows title + meta (+ viewed X/Y); the description is collapsed by default and again for each new PR, scrolling inside the header past 320 px. Files are ordered by `FileTree::file_order()` (folders first) once at load, so the tree and the diff share one order and file indexes. The tree (`uniform_list`, 24 px rows) has a progress bar, the filter (`filter_rendering.rs`): a Hide viewed switch, a Kind row (Code/Tests/Generated/Moved, one kind per file) and a Type row (extension, or the name of a file without one; alphabetical by name without the dot, ignoring case; collapsed it shows the 8 with the most files + more), where a click picks a chip (show only the picked ones of that row; rows narrow together), ⌥-click hides it (struck through), counts say what a chip would show given the other row (0 is dimmed), and a summary line `Showing x of y · … · Reset`; tri-state folder checkboxes (mark all / unmark all), and highlights the file at the top of the diff; clicking a file scrolls to it. A file the filter hides keeps an empty row range (`DetailRowList::file_start` is `None`), so it vanishes from the diff too; `AllFilesHidden` says why the diff is empty. Tree visibility, Hide viewed and hidden kinds persist (`ReviewLayoutState`); picked chips, file types and collapsed folders reset per PR. The empty diff names what narrows it.
- Stacks: the queue's refresh fills `PullRequest::stack` (GraphQL; on failure the last known memberships stay). The sidebar groups a stack under a header at the place of its most recently updated listed layer, with every layer bottom first once its layers are known (`QueueRow::OtherLayer` for layers the tab's list lacks: muted, clicking opens them like the stack map); layers asking for the viewer's review carry a Review badge, and the header says how many are yours / to review. The queue keeps the listed stacks' layers (`stacks`): read from the cache at launch, checked with GitHub after each refresh (`fetch_stack.rs`, shared with the detail; free on 304); clicking the header opens the combined review (highest listed layer, from the lowest unmerged one) and highlights it while shown (`DetailEvent::TargetChanged` redraws the sidebar); its chevron collapses the group. The detail reads the stack from the cache, then checks it with GitHub on every shown version (free on 304), and shows the stack bar (layer N of M, ‹ › neighbours, Layer/Combined) and the stack map (click: open layer; ⇧-click: start the combined range there). Opening a layer emits `DetailEvent::OpenLayer`; the queue selects it from a list or fetches it (`pull_request_by_number`, cached, `SelectionOrigin::StackLayer`, survives refreshes). `ReviewTarget::decide`: combined = base of the first layer (the chosen start, else the lowest unmerged) to the head of the shown layer; it waits (`AwaitingStack`) for the layers. Combined viewed marks are their own `ViewedScope`. The review mode persists in the review layout.
- Loading indicator: the background load reports `LoadProgress` through a `futures` mpsc channel (checking commits, files n of total from `RevisionCheck`, MB of a combined diff in 256 KB steps, building diffs); the header pill (pulsing dot), a progress line under the header (determinate when the share is known, else sweeping) and a loading card in place of the files show it; stack checks and syntax batches show in the pill too. The sidebar pulses while refreshing or opening a layer.
- Diffs: built on the background executor when files load and when whitespace/highlight settings change (layout/wrapping only redraw); `LoadedFile` holds `Arc`s of file + diff. `FileReviewState` owns viewed/collapsed per file; viewed marks persist with a `PatchFingerprint` and reset when the patch changes. Files over 400 changed lines and viewed files start collapsed.
- Syntax colors: after load and after a rebuild, `highlight_syntax` runs one background batch per core and applies each batch as it finishes (matched by the diff's `Arc`, so a rebuilt diff ignores stale colors). Files draw plain until then. A real 99-file / 4.5k-line PR takes ~0.7 s single-threaded; `code_highlights` merges syntax colors with changed-range backgrounds into non-overlapping runs.
- GitHub usage (`fetch_changed_files`, `fetch_combined_files`, `fetch_stack`): files cached for the PR's `updated_at` → no request; otherwise one commit check (`pull_request_revision`, conditional on the stored ETag, free when unchanged) → same commits: confirm the cached files; new commits or nothing cached: fetch all pages and cache. Measured on a real 130-file PR: relaunch 0 core requests, after a comment 1, cold 3. A combined range is read from the cache by its two commits, else one `.diff` download. The queue refresh is 2 search requests + 1 GraphQL request; after it, `delete_expired(AppSettings::cache_ttl)` runs.
- Flow: show cached queue at launch → refresh from GitHub in background → cache → clean up expired data.
- Panel widths: the sidebar (240–720 px, default 380) and the side panel (220–640 px, default 300) resize by dragging the `ResizeHandle` between panels (the handle is the divider line, not a border, so it overlaps no scrollbar); each owner keeps its width and records it (`record_sidebar_width` / `record_side_panel_width`, batched writes).
- Restore: window placement, panel widths, queue tab, selected PR by id (matched against the cached lists, else a cached PR in no list (a stack layer), then the first refreshed lists, else dropped), detail scroll as `DetailScrollPosition` (row + offset; applied when the files load, so no heights are needed).
- Performance: the detail pane renders only visible rows (`list` with `measure_all`, overdraw 600 px). Collapse/viewed toggles `splice` one file's rows; settings/load `reset` and re-anchor on the file at the top. Benchmark (100-file PR, split + wrap, 45 px/frame): 273 ms → 8.3 ms per frame. Scroll mode scrolls each file sideways via a per-file offset on horizontal gestures (rows are separate, so no per-file scroll container).
- Scrollbars: wrap the scroll container in a `relative()` div with the container `size_full()` and a `VerticalScrollbar` beside it: `ScrollbarTarget::Handle` for a div or `uniform_list` (`handle.0.borrow().base_handle.clone()`), `ScrollbarTarget::List` for a `list`. The thumb is painted at paint time.
- Diff selection: `DiffSelection` (side + anchor/head as row + byte) lives in `PullRequestDetail`, so it survives scrolling; cleared on any row rebuild/splice. Each painted code cell registers its `TextLayout` in `CodeSegments` from a paint-time `canvas` (only painted texts, so bounds exist; measured-only rows never register); the registry is cleared in `render`. Drag past the pane edge autoscrolls; split selections stay in one column; copy (`selected_diff_text`) is code only. A press outside code clears the diff selection without taking focus, so the description keeps its own selection.
- Wrapping text in a flex row needs `min_w_0()` on its flex item (see the skill's gpui rules); the detail pane and Markdown list items have it.
- Window display: gpui reports and takes window bounds relative to the window's display, so the placement saves the display's UUID (`display.uuid()`, stable across reconnects) and `launch_app` reopens with `display_id`; a missing display falls back to the main one, and placements that do not fit their display open centered.
- gpui on macOS opens windows by content size but reports `window_bounds` as the frame (title bar included): save `viewport_size` for windowed mode or the window grows each relaunch.
- UI changes are verified by running the app; view logic that can be tested without a window lives in plain types (`SelectionAfterRefresh`, `SelectionRestore`, `RefreshSchedule`).
