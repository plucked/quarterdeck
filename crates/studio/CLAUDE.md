# qd-studio

| Module | Holds |
|---|---|
| `studio`, `studio_page`, `studio_widget`, `callout_tone`, `studio_table`, `table_role` | the studio: a lead and 1–10 pages read in order (6 for a single pull request, up to 10 for a combined stack of many layers, as the guide says) (title for the tab, one-line summary), each with widgets in reading order (section, callout, code excerpt, code comparison, table/trace, scope, tour, graph, sequence); a presentation of the change, not a review: there are no findings |
| `studio_graph`, `graph_node`, `graph_edge`, `node_role`, `edge_style`, `diagram_change` | `StudioGraph`: boxes (label, detail, role, group index, anchor) in boundaries, joined by labelled arrows (control/data/async/optional) between node indexes; parts marked same/added/removed (`has_changes` → drawn before and after) |
| `studio_sequence`, `sequence_lane`, `sequence_message`, `message_style` | `StudioSequence`: lanes (label, role) and messages in time order between lane indexes (call/reply/async, note, anchor) |
| `change_scope`, `studio_tour`, `tour_step`, `step_weight` | `ChangeScope` (what changes, what stays the same, what is mechanical; blank items dropped, an empty scope rejected) and `StudioTour`, the reading order: 2–9 steps (title, explanation, weight core/supporting/mechanical, optional anchor cut to its first line, since a step links to where its piece starts; a start line outside the diff rejects the tour) |
| `code_anchor`, `code_side` | `CodeAnchor`: path, base/head side, inclusive 1-based line range |
| `anchor_targets` | `AnchorTargets`: the line numbers each listed diff shows per side (renames answer to both paths); `check` refuses ranges whose first or last line is not shown (lines between may fall in a gap between hunks: the excerpt shows a gap row), unknown files, spans over 80 lines |
| `parse_studio`, `checked_studio`, `rejected_widget`, `wire_anchor` | agent output → `CheckedStudio` (kept widgets per page + rejected with reasons, named `Page: widget`; pages past the tenth rejected whole); a shape mismatch is an error |
| `parse_diagram` | graph and sequence checks: the agent's ids to indexes (unknown or repeated id rejects), 2–14 nodes, ≤ 24 edges, ≤ 5 groups, 2–6 lanes, 1–24 messages, every box/arrow/message labelled, an arrow only in pictures (before/after) both its boxes are in, anchors in the diff |
| `studio_schema` (+ `.json`), `studio_guide` (+ `.md`) | the answer's JSON Schema, valid for Claude's `--json-schema` (draft-07) and Codex's `--output-schema` (strict: all required, nullable); the authoring guide appended to the system prompt |
| `reader_familiarity` | `ReaderFamiliarity` (Expert / Overview, the default / Newcomer): how well the reader knows the area; the prompt's "The reader" section sets the onboarding (no background / the touched mechanisms and terms / a Background page drawn from the surrounding code in `head/`) |
| `request_layer` | `RequestLayer` (number, title): a stack layer a combined brief spans; the prompt lists them bottom first and asks the brief to follow them where the change builds up layer by layer |
| `studio_request`, `studio_request_file`, `file_listing`, `studio_prompt`, `studio_prompt_message` | the user message: PR, its fenced description or, for a combined range, every stack layer with its fenced description (3k chars each, 60k in all; the app reads them from the cache, else one request per layer), file list, the reader, diffs numbered `base head mark text` up to 300k chars, chosen code first, then documentation, then tooling under dot-folders (`ListingPriority`; tree order would spend the budget on `.github`/`.claude`), shown in tree order; with a workspace every diff is also in `diffs/<path>.diff` (`StudioPrompt::workspace_diffs`, written by the app with `WorkspaceDiff::write_all`, which skips paths leaving the folder) and `targets` holds every diff's lines, else only the listed ones |
| `output_lines`, `stop_child` | cancelling a run's processes: `OutputLines` reads a child's stdout/stderr on a thread (lines end at `\n` or `\r`) and `next(cancel)` checks the cancel flag every 200 ms while waiting, so a silent process (stalled fetch, silent model) still stops; `stop_child` sends `SIGTERM` (the `kill` command), waits up to 2 s, then `SIGKILL`, and reaps it |
| `new_process_folder` | a new folder `<prefix><pid>-<nanos>` (workspaces, the empty folder of a run without one); the pid is what the orphan sweep reads |
| `text_tail` | `tail`: the last characters of git's or Claude Code's error output, for error messages |
| `find_claude`, `run_claude`, `claude_event`, `agent_progress`, `agent_answer`, `agent_run_error` | headless Claude Code run and its `stream-json` events (tool starts tell reading from writing the answer); `AgentAnswer` also carries the model (init event) and the transcript (every line but `stream_event`) |
| `brief_record`, `write_brief_report` | `BriefRecord`: everything about how one brief was made (subject, layers, head commit, reader, code access, prompt, raw answer, transcript, rejected, cost, session, model, duration); `write_brief_report` writes `report_root()/<UTC stamp>-<owner>-<name>-<number>/` (`~/Library/Application Support/Quarterdeck/brief-reports`, shared by all builds): `report.md` (the reader's words, the brief, the run, what it read, the files, where Quarterdeck makes the brief), `prompt.md`, `system-prompt.md` and `schema.json` as compiled into the build, `answer.json`, `rejected.md`, `transcript.jsonl` |
| `workspace_diff` | `WorkspaceDiff` (path, numbered listing), `DIFFS_FOLDER`; `write_all` writes `diffs/<path>.diff` |
| `code_access`, `workspace_source`, `prepare_workspace`, `review_workspace`, `workspace_progress`, `workspace_error`, `workspace_root`, `clean_orphan_workspaces` | the review workspace: `~/Library/Caches/de.plucked.quarterdeck/review-workspaces/workspace-<pid>-<nanos>/` with the head commit's files in `head/` and the pull request's diff (given by the app, from its loaded patches) as `change.diff`; removed on drop; folders of dead pids swept at launch |

- JSON is the wire format to the agents only: wire types derive `Deserialize` privately in `parse_studio.rs`; nothing derives `Serialize`; studios are not stored as JSON.
- The agent never quotes code: widgets carry anchors, the app cuts the lines from its diff. Anchors are checked against the diffs the prompt listed, not against all files.
- `run_claude` confinement: `--restricted` (no code-running tools, no settings files, file tools kept to the working folder), `--safe-mode` (no CLAUDE.md, hooks, skills, plugins: a checked-out repository's instruction files do not load), `--strict-mcp-config`, `--permission-mode dontAsk --permission-prompts none`, `--max-budget-usd 5`, prompt on stdin, `--include-partial-messages` for progress (tool input arrives as `input_json_delta`; only `StructuredOutput`'s counts as the answer). With a workspace: cwd there, `--tools`/`--allowedTools Read,Grep,Glob,Agent` (Explore subagents for large changes: verified with 2.1.318 that a subagent gets only `Glob`/`Grep`/`Read`, no Bash, and `--restricted` refuses its reads outside the folder); without: a new empty temp folder and `--tools ""`. Verified (2.1.318): reads outside the folder are refused, no shell, a repository hook and CLAUDE.md are ignored. Setting the cancel flag stops the process within 200 ms, even while it prints nothing (`stop_child`: `SIGTERM`, 2 s grace, `SIGKILL`).
- `prepare_workspace`: `git init --bare .store`, `git fetch --depth 1 --no-tags <url> <head>` (GitHub serves commits by SHA), `git archive | tar -x` into `head/` (no `.git`; LFS files stay pointers, `GIT_LFS_SKIP_SMUDGE=1`), the given diff written to `change.diff`, then `.store` removed. Git runs with `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM`, no prompts; the token is an `http.https://github.com/.extraheader` through `GIT_CONFIG_COUNT`/`KEY_0`/`VALUE_0`, so it is in no file, URL or argument the agent could read. Fetch progress (`Receiving objects: N%`) is read from stderr through `OutputLines`; cancelling stops git the same way as the agent.
- Verified with Claude Code 2.1.318: `--json-schema` works with `stream-json`; the result line carries `structured_output`, `total_cost_usd`, `session_id`.
