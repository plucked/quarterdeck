# qd-studio source

The review studio as data: the widgets an AI agent may use to explain a pull request (a lead and pages of sections, callouts, code excerpts and comparisons, tables and traces, a scope, a reading order, graphs and sequences), the code anchors that tie them to lines of the diff, and the checks that drop a widget whose anchor the diff does not show. It also writes what the agent is given (a numbered listing of the diffs, the JSON Schema of the answer, the authoring guide) and prepares a shallow checkout of the head commit with its supplied diff (`head/`, `change.diff`) and runs Claude Code headless and confined in it with read-only tools, following its event stream for progress. It does not draw anything, call the GitHub API or store studios; the app gives it the loaded diffs and renders the result.

Headless runs have no app-imposed spending cap; cancellation remains available.

It also defines and validates guided review buckets: any number of ordered, described groups covering all changed paths, with ordered reading items and guidance within each bucket. The agent also chooses the file sequence inside each item, which remains ordered through validation and publication. Related binary, generated or mechanical files can form one explicitly suggested item. Optional suggestions identify mechanical buckets suitable for bulk acknowledgement. Folder selectors expand once at their position into exact files in frozen inventory order, keeping each file's first occurrence. Repeated membership within a bucket, missing guidance and unknown paths reject new plans; legacy bucket paths remain readable. The smart-filter prompt shares the file inventory and budgeted diff listings with briefs. Its legacy schema-only runner retains Opus/high effort and Read, Grep and Glob; the production MCP runners also allow delegated read-only exploration.

Guided reviews now also have a repairable path: a frozen run snapshot owns a revisioned draft exposed through a small, per-run MCP endpoint. Claude replaces complete buckets, receives overlap and coverage diagnostics, and seals a valid guide. The blocking runner accepts only the sealed receipt echoed by a successful Claude completion and process exit. It returns typed buckets plus run metadata and bounded validation audit; the app performs publication. Private adapter shapes decode JSON into plain domain candidates. MCP also owns candidate encoding and its wire-size limit, applied within the draft's replay and atomic replacement boundary. The transport's scoped runtime stays outside this pure domain code. Legacy schema-only generation remains available for rollback and existing tests.

Brief authoring uses the same MCP process lifecycle with complete page replacements and a separately versioned lead. Strict page validation returns anchor and widget errors for repair instead of publishing a lossy page. The final result carries the typed studio and its accepted full wire artifact for reporting, plus the sealed receipt and run metadata. Both artifact runners keep publication outside the endpoint.
