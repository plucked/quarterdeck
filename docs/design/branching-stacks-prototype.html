Design notes

How a PR gets a parent

Use the order supplied by a GitHub stack first. For other links, match a child’s base repository and branch to one known open PR’s head repository and branch. Multiple children can match the same parent. Treat the default branch as a boundary. Unrelated PRs into main stay separate.

What a combined review covers

Walk from the lowest unmerged ancestor to the selected PR. Compare the first layer’s base with the selected head. The other side of a fork stays outside the diff. Layer mode shows the selected PR’s own changes.

What the queue counts

Show the connected stack when any member needs review. Only requested PRs count toward “To review”. Dimmed ancestors remain selectable. A group header folds the group, leaving the selected PR and review path in place.

When evidence is incomplete

Start with PRs already known to Quarterdeck. Missing branch or fork identity, ambiguous parents, and links that would form a cycle leave the inferred connection unresolved. Recompute links after a retarget. Preserve selection by repository and PR number.

What inference enables

A branch match groups PRs for navigation and combined reading. GitHub’s declared stack controls its native stack actions. For an inferred link, merge still targets the individual PR.

Decision for this prototype

Try switching from #421 to #418, on the other side of the fork. Which view makes it easiest to tell that they share #412 and which changes you would review? If two PRs target the same feature branch but its parent PR is missing, should that branch appear as a group? This proposal waits for a known parent PR.
