# Quarterdeck

macOS desktop app (Rust + gpui) for reviewing GitHub pull requests efficiently: the viewer's own and review-requested ones, including GitHub stacks (layer by layer or combined), with line comments that either form a GitHub review (approve / request changes / comment) or stay local to copy for an AI agent or send to an active Claude Code session. Personal tool shared with colleagues: macOS on Apple silicon only, distributed as signed, notarized GitHub releases that update themselves.

## Workflow
- Remote `origin`: `git@github.com:plucked/quarterdeck.git` (public). Work directly on `main` and push it. Small atomic commits, prefixed `feat:`/`fix:`/`refactor:`/`docs:`/`chore:`/`style:`/`test:`.
- Rust conventions: skill `knowledge-writing-rust-in-quarterdeck` (`.claude/skills/`). Load it before touching `.rs` or `Cargo.toml`.
- Keep this file and each crate's `CLAUDE.md` current in the same commit as the change. Compact: facts only.
- `README.md` describes the features and how to run the app for people; update it when a user-facing feature or the way to run it changes.

## Crates
| Crate | Path | Holds |
|---|---|---|
| `quarterdeck` | `crates/app` | gpui binary: window, views, background tasks, UI state restore |
| `qd-github` | `crates/github` | blocking GitHub client (`ureq`): REST, plus GraphQL for stacks and reviews (threads, submit, edit, resolve); its data shapes |
| `qd-claude` | `crates/claude` | fresh local Claude session inventory and one-way review-note submission to a verified inbox |
| `qd-cache` | `crates/cache` | the local SQLite database: cached GitHub data + UI state, with migrations |
| `qd-markdown` | `crates/markdown` | GitHub-flavored Markdown → typed document (`pulldown-cmark`) |
| `qd-syntax` | `crates/syntax` | syntax colors for diff hunks (`syntect` + bat's grammars via `two-face`, Graphite theme) |
| `qd-diff` | `crates/diff` | per-file patch → hunks, side-by-side rows, inline word/char changes, whitespace folding (`similar`) |
| `qd-file-tree` | `crates/file_tree` | changed files as a folder tree (shared file order), test/generated detection, file filters, file icons by path |
| `qd-video` | `crates/video` | movie frames decoded by macOS AVFoundation into BGRA (the startup splash) |
| `qd-agent-mcp` | `crates/agent_mcp` | per-run authenticated loopback MCP transport using the official Rust SDK; the sole scoped Tokio exception, behind a blocking API |
| `qd-studio` | `crates/studio` | the review studio: widgets an AI agent writes to explain a PR (lead and pages of section, callout, code excerpt/compare, table/trace, scope, reading order, graph, sequence), anchors checked against the diff, the agent's prompt + JSON Schema, a confined headless `claude -p` run |
| `qd-update` | `crates/update` | self-update: release manifest (`latest.json`), download with SHA-256 check, signature check, bundle swap, relaunch |

Only the app depends on gpui. Library crates expose blocking, UI-free APIs; the app runs them on `cx.background_executor()`. The sole Tokio exception is the private transport runtime in `qd-agent-mcp`, required by the official Rust MCP SDK.

## Run & check
```bash
bacon                                       # rebuild + relaunch on save (job `app`, from the dev bundle with icon); UI state is restored
bacon gallery                               # same, with Window → Brief Gallery opened at launch
cargo run                                   # needs GITHUB_TOKEN or `gh auth login`
cargo run -- --no-splash                     # open immediately without the startup movie or fade
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo clippy --workspace -- -D warnings
cargo test --workspace
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --workspace
```

App bundle: `packaging/macos/bundle.sh` → `target/bundle/Quarterdeck.app` (`aarch64-apple-darwin` only, ad hoc signed); `--dev` keeps `target/debug/Quarterdeck.app` (debug binary hard-linked, icon remade only when `AppIcon.png` changes, startup movie copied into `Resources`), which bacon's `app` job runs so the app has its icon and name (`de.plucked.quarterdeck`, `Info.plist` template, version from `[workspace.package]`, `AppIcon.icns` from the 1024 px `AppIcon.png`). Started from Finder the app gets launchd's environment: no `GITHUB_TOKEN`, no Homebrew `PATH`.

Release: the user-invoked skill `/release [patch|minor|major|X.Y.Z]` (`.claude/skills/release/`) picks the version (minor with a `feat:` since the last tag, else patch), writes user-facing notes, bumps and pushes, then runs `packaging/macos/release.sh [--notes FILE] [--dry-run]`, run locally (no CI): checks (clean tree, HEAD pushed, gh's own login can push (gh runs without `GITHUB_TOKEN`/`GH_TOKEN`, which may hold a token that cannot create releases), tag `v<version>` unused, notary profile `quarterdeck-notary`, movie not an LFS pointer), `bundle.sh`, re-signs with `Developer ID Application: Rainer Heynke (97ZZEC8R43)` (hardened runtime, timestamp; no entitlements needed), notarizes + staples the app (zip) and the DMG, writes `latest.json` (version, notes, `zip_url`, `zip_sha256`, `zip_size`, via `plutil`), and publishes GitHub release `v<version>` as a draft first, then public, so `releases/latest/download/latest.json` always has its zip. Output in `target/release-artifacts/<version>/`. Notes default to the `feat:`/`fix:` subjects since the last `v*` tag.

Devbox: `devbox.json` pins rustup, bacon, gh, sqlite; `devbox run app | dev | check | test`. `devbox.lock` pins the resolved versions (Devbox 0.19); `devbox update` moves them.

## Facts
- Startup preserves a restorable selection; when none remains, it opens Mine's first stack (combined review), then its first standalone PR if there are no stacks. A user choice cancels the pending startup fallback.
- The view tabs (Summary / Diff / Guided review / Brief, with a stack's Layer / Combined beside them on Diff and Guided review) sit in the window's top bar, centered on the window; the pull request header below is one 40 px row (status, title, repository, author, branches, update time). Side-panel navigation uses the same quiet rounded tabs. The main Guided review tab has its own step workspace and Guide navigator; Diff uses the ordinary file tree with Kind and Type filters; guide buckets never filter it. Review reveals GitHub / Local; Actions reveals Merge / Close within the same animated bubble. The Focus Drawer has two header rows: scoped search and Filters, then one horizontal viewed count/bar with Hide viewed and Reset. Folder checkboxes act on descendants matching the active filters. Plan item and bucket actions include hidden members. Each action offers Undo. Guided reviews guide an ordered walkthrough with explicit file groups. File content search indexes complete texts at the loaded revision in the background, with line snippets and honest coverage.
- In an open diff, ⌘F searches the current file’s displayed code. Double-click selects a word by default. Settings → File Diff can enable double-click to comment. GitHub comment editors and the review summary share rich text, Markdown source and preview. Inline GitHub drafts can include suggested changes for a range on the new side.
- Folder rows show recursive changed-file counts. Settings → Appearance offers a folder heatmap (on by default), using theme-derived blue-to-orange colors; folder counts, line totals and heat follow active filters (including Hide viewed), and stay stable when folding.
- gpui 0.2.2 from crates.io, `default-features = false`, features `font-kit` + `runtime_shaders` (no Metal Toolchain needed to build).
- Token: `GITHUB_TOKEN`, else the token saved in the login Keychain from Settings → GitHub (generic password, service `de.plucked.quarterdeck`, account `github-token`; checked with `GET /user` first; the app restarts to use it), else `gh auth token` (`gh` on `PATH`, `/opt/homebrew/bin`, `/usr/local/bin`). Without one the app shows cached data only.
- Updates: `AppUpdater` checks `github.com/plucked/quarterdeck/releases/latest/download/latest.json` (no API budget) 15 s after launch and every 4 h; a newer version is downloaded to `~/Library/Caches/de.plucked.quarterdeck/updates`, SHA-256 and size checked, unpacked with `ditto` into `.Quarterdeck.app-update` beside the bundle, verified (`codesign` against the Developer ID requirement of team `97ZZEC8R43`, `spctl` for notarization, `CFBundleShortVersionString`), and installed by two renames on quit or on Restart to update (relaunch by a detached `sh` that waits for the process to exit, then `open`s the bundle). Off when not running from a release-signed bundle (dev builds, `cargo run`), when translocated, or when the bundle's folder is not writable.
- A database migrated past the app's `SCHEMA_MIGRATIONS` (a newer app ran) is refused; startup failures show in an `osascript` alert, since a Finder launch has no terminal.
- Database files are scoped to the GitHub account ID under `~/Library/Application Support/Quarterdeck/accounts/` or `Quarterdeck Dev/accounts/` for debug builds. A known credential restores its own offline profile. The unassigned legacy `cache.sqlite` is preserved.
- Runtime boundary: GPUI executors own app work. Only `qd-agent-mcp` owns a private Tokio runtime, on its transport thread, because the official Rust MCP SDK requires it. No Tokio or SDK types enter app or review-domain APIs.
- Everything stored is typed SQLite columns, cached GitHub data included; never JSON (see the skill's Persistence section).
- Queue refresh runs at launch, on ⌘R, after five minutes, on activation after a minute, and when watched repositories change. Mine and To review follow REST search pages. Active direct requests, including re-requests, determine which PRs and stacks appear in To review. Each stack shows all its layers and dims those without a request. The app fetches branch, viewer review and stack metadata for the returned PR numbers in batches of 100 per repository. Others reads every page of open issues and PRs on its first sync in a session. Subsequent refreshes merge changes since the last complete sync and remove closed PRs. An incremental sync beyond 20 pages falls back to a full sync. Rate limits and repository errors retain prior data.
- Others tab (`cmd-3`): open PRs by others in the watched repositories (Settings → Repositories: `owner/name` or a GitHub link, checked with `GET /repos/{o}/{r}`; quick picks from the queue's repositories; a preference in `AppSettings`). Every watched repository shows a header, even with nothing shown; its filter button opens an inline filter under it: Hide drafts, Hide review requests, Updated within (any / 7 / 30 days), Labels and Authors chips (click: only those; ⌥-click: hide; counts given the rest; a chip that would show nothing is left out unless picked or hidden; author chips show the GitHub avatar, label chips the label's color). Filters are per repository UI state (`others_filters` + `others_filter_chips`, saved only while they narrow something), applied locally, so they cost no requests. A failed others' fetch keeps the last list and shows `Others: …` in the tab.
- Hidden branches (Settings → Filters): global rules, each a wildcard pattern (`*` any run, `/` included; `?` one character; case-sensitive) and the branch it looks at (from = head, into = base, or either), a preference in `AppSettings` (`hidden_branch_rules`). The queue keeps every fetched PR (`fetched`, which the refresh syncs from) and shows `fetched` without the hidden ones in all three tabs (`lists`); a PR whose branches are not known yet shows. Changing the rules only re-filters: no request.
- Queue refresh preserves the open diff for the same head and base commits. Combined reviews follow the refreshed stack range.
- PR file loads remain cache-first; over 500 changed files, they try a compare `.diff` before the paginated files API. Failed or incomplete diffs fall back to pages unless GitHub is throttling. Incomplete file sets never replace the cache.
- GitHub requests are minimized: whole file texts load lazily on context expansion or the first nonempty Contents query, by blob SHA (one REST request; by path at the shown revision (base for deleted files), one GraphQL request, when the SHA is abbreviated or unknown), cached by blob SHA for good (content addressed); cached files are reused while the PR's commits are unchanged (checked with a conditional request, free on 304); stacks are checked with a conditional request; a combined stack diff is one `.diff` download per commit pair, cached for good (commits never change); unused cached data expires after the TTL (Settings → GitHub, default 1 day).
- Stacks: GitHub stacked PRs (GA Oct 2026). Membership from GraphQL `PullRequest.stack`/`stackEntry`; layers from `GET /repos/{o}/{r}/stacks/{number}` (bottom first, each targets the layer below). Search/issues ids differ from pulls ids (`StackLayer::pull_request_id`): match layers by number.
- Lints: clippy `pedantic` (warn, `-D warnings` in checks), `module_inception`/`missing_errors_doc`/`must_use_candidate` allowed, `unsafe_code = "deny"` (one exception: `qd-video`'s `video_reader.rs`, the AVFoundation calls).
- Brief: Summary / Diff / Guided review / Brief switches between the PR description, ordinary diffs, guided steps and an AI explanation. Write brief prepares a shallow head checkout (LFS pointers only; GitHub credential via environment), numbered diffs and frozen anchor targets. `run_brief_review` uses a per-run authenticated MCP endpoint: Claude replaces complete pages, receives schema/widget/anchor diagnostics, repairs them and seals a receipt. Only a matching successful CLI completion and exit can publish. `BriefPane` keeps an existing brief readable during replacement and on failure; a shared `ReviewPublicationGate` and SQLite generation reservation protect cancellation, snapshot changes and stale writers. Typed tables retain content, model/cost/session metadata, receipt and bounded repair audit. MCP briefs record the comparison base so base-only changes also mark them outdated. Report exports the full accepted artifact separately from the receipt/audit, with the complete authoring guide and both artifact/completion schemas. Raw answers and transcripts remain session-only. Window → Brief Gallery renders sample widgets without a model run.
- Checks (side panel tab, prototype): the shown pull request's head commit checks (in a stack, the shown layer only) from GraphQL `statusCheckRollup` (100 per request; after all pages, only the newest run per stable workflow ID supplies jobs, so superseded failures do not affect the displayed verdict; with the base branch's required checks from its protection rule and the rulesets on it (`baseRef.rules`, readable by a fine-grained token); required ones nothing reported show as Expected, as on GitHub), read when the tab shows and every 30 s while some are pending; not cached. A verdict and outcome bar, flat Failed / In progress sections, then every check by workflow → called workflow (`Group / job`) → job, folded, skipped hidden until asked. GitHub withholds check runs (FORBIDDEN nodes, REST 403 asking for `checks=read`) from a fine-grained token without the Checks permission; then the Actions jobs stand in (`workflow_job_checks`: runs by `head_sha`, the newest per workflow, their latest jobs, plus commit statuses; ~1 core request per run, 14 for seed#36469), without required marks or other apps' checks; a token without Actions read either sees only the rollup and count. GitHub starts no `pull_request` workflows while a merge commit cannot be built: the query reads `mergeable`; `CONFLICTING` names the PR itself, `UNKNOWN` (upper stack layers above a conflicting one stay unknown) asks the open layers below (one aliased GraphQL request) for the lowest `CONFLICTING` one; the tab then says `No checks: merge conflict` and which PR to fix (seed#36475: #36410 conflicts with develop).
- Startup: the main window opens hidden and see-through while `StartupSplash` plays `crates/app/assets/startup-intro.mp4` (Git LFS, `*.mp4`; copied into the bundle's `Contents/Resources`), so the queue loads and refreshes underneath; frames are paced by the display's refreshes, not timers; at the end (or a click) the main window draws its first frame, then the splash fades out over 1 s as the main window fades in. Without the movie (a clone without LFS has a pointer file), or with `--no-splash`, the main window shows at once without a fade.

- Guided review uses `qd-studio::run_guided_review` and `qd-agent-mcp`, with a private loopback endpoint and fresh env-only credential per run. The domain owns frozen inventory, atomic bucket replacement, revision/idempotency checks, bounded repair diagnostics and a sealed readiness receipt. The host requires the matching successful Claude completion and process exit before generation-checked SQLite publication. The old guide remains on failure. Completed guide/brief save failures retain the exact draft, receipt and metadata for a session-local Retry save; retries reuse the existing reservation without another model run. Discard, a new generation or a changed snapshot clears the pending draft. Failed transactions release the attempt gate; revision invalidation during publication prevents stale retries. The MCP runner deliberately omits `--safe-mode` (it suppresses MCP) and uses explicit instruction/hook/settings exclusions plus exact tool permissions; Brief uses the same process lifecycle with its own page/anchor contract. No app-imposed Claude spending cap.
